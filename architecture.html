ADR-001 · JAWEBFLOW · COST & LATENCY ECONOMICS IN PRODUCTION

Dynamic Threshold Routing Between Bounded RAG and Short-TTL Explicit Context Caching

Multi-tenant SMB merchants have wildly uneven knowledge bases—ranging from 3 short FAQ notes (~256 chars) to 60+ product sheets (~20,000 chars). Applying one single retrieval strategy across all tenants either wastes tokens on every message or burns hourly cache storage fees.

THE DECISION & MECHANISM

Implemented a pre-flight character/token gate (cacheableChars) before network calls. Prompts below Gemini's 4,096-token caching floor bypass cache creation (zero wasted round-trip) and run deterministic bounded RAG. Catalogs ≥ 4,096 tokens create an explicit context cache with a short 10-minute TTL—active conversations re-read the entire merchant catalog at 10% token price ($0.025/M vs $0.25/M).

WHY NOT PINECONE OR 24H CACHING?

External vector DBs add network hops, sync drift, and monthly base costs per tenant. Meanwhile, caching a 6,700-token merchant catalog for 24h costs ~$0.16/day in storage ($1.00/M tokens/hr)—more than a small shop saves! A 10-minute sliding window captures bursty customer sessions while letting idle caches expire for free.

Workload (Measured in Code) Before After Routing Measured Delta
Site Chat (5,469-char KB) 8,985 chars (~2,247 tok · $0.56 / 1k msgs) Bounded RAG: 4,687 chars (~1,172 tok · $0.29 / 1k) −48% input cost
Merchant Chat · 60 SKUs (19,908 chars) ~6,700 repeated tok ($0.65 / 1k msgs) Explicit Cache (TTL 10m, read at $0.025/M) −74% ($0.17 / 1k msgs)
ACCEPTED TRADE-OFF & KNOWN LIMIT

Explicit context caching becomes net-positive at ~1,300+ messages/month for large catalogs; for ultra-low-traffic large catalogs (1 single message every few hours), the one-time cache write ($0.083/M) slightly offsets savings—mitigated by keeping TTL tight at 600s.

ADR-002 · JAWEBFLOW VOICE · REALTIME AUDIO LATENCY & GUARDRAILS IN PRODUCTION

Zero-KB Voice System Prompt with On-Demand Bounded Tool Retrieval

In bidirectional WebRTC/Live voice sessions, every token inside the system prompt is re-billed on every spoken turn—even when the caller just says “Hello”, “Okay”, or “Thanks”. Stuffing the merchant's product catalog into the voice prompt inflated per-turn latency and token burn.

THE DECISION & MECHANISM

Stripped the entire merchant knowledge base out of the voice system prompt (reducing turn prompt from 8,676 chars to 3,520 chars: −59%). When—and only when—a caller asks a factual question, the voice model invokes chercher_information, returning at most 900 chars (~225 tokens). Conversational turns (“bonjour”, “merci”) trigger zero retrieval and pay zero KB tokens.

HONEST RETRIEVAL GUARDRAILS

Added stop-word stripping (“est”, “vos”, “quelle”) and a strict zero-overlap rule: if the caller asks about a product with zero matching terms in the merchant's KB, retrieval returns empty instead of falling back to generic company blurbs—forcing the agent to say “I don’t have that information” rather than hallucinating.

ACCEPTED TRADE-OFF & KNOWN LIMIT

Factual questions incur one lightweight HTTP tool round-trip compared to having the full KB pre-stuffed in context, traded deliberately for −59% per-turn cost and deterministic hallucination control.

ADR-003 · SAWTIFY · AGENT ECOSYSTEM & API SECURITY IN PRODUCTION

Dual-Auth Remote MCP Server (OAuth 2.1 + PKCE & SHA-256 Developer Keys)

To make Sawtify's dialectal voice engine usable directly inside Claude Desktop, ChatGPT Developer Mode, Claude Code CLI, and n8n/Make workflows, the platform needed both interactive user consent (OAuth 2.1) and headless server-to-server keys without exposing raw secrets in storage.

THE DECISION & MECHANISM

Built a spec-compliant MCP server (@modelcontextprotocol/sdk) behind Cloudflare edge routing (/mcp, /.well-known/oauth-authorization-server, dynamic client registration /oauth/register, PKCE S256). For CI/CLI & backend integrations, Developer API v1 issues swt_beta_* tokens shown once at creation and persisted strictly as SHA-256 digests, gated behind a >1,000-point wallet check.

FAIL-SAFE SECURITY POSTURE

If MCP_OAUTH_SECRET (≥32 chars) is absent at boot, the MCP connector disables itself cleanly rather than running with weak signing defaults. Database leaks cannot expose usable developer API keys because plaintext keys are never stored.

ACCEPTED TRADE-OFF & KNOWN LIMIT

Single-use OAuth authorization codes live in-memory on a single Render instance (5-minute TTL + PKCE); a server restart during those 5 minutes simply asks the user to re-approve once—avoiding Redis operational overhead at current scale.

ADR-004 · SAWTIFY LIVE v5 · DIALECTAL VOICE & TELEPHONY IN PRODUCTION

Decoupling Live Multimodal Reasoning from Dialectal TTS Rendering & Server-Side Call Metering

End-to-end native speech-to-speech models handle English well, but flatten Algerian Darija pronunciation and prevent merchants from using their custom brand voice during live calls. In addition, client-side timers can be tampered with to bypass call billing.

THE DECISION & MECHANISM

Defaulted Live Call output to hybrid mode (AGENT_LIVE_OUTPUT_MODE=sawtify_tts): Gemini Live processes bidirectional audio and executes tool calls with explicit order-confirmation guardrails, emitting text that Sawtify's 24 kHz TTS vocalizes with explicit Algerian Darija phonetics (capped at 700 chars/turn, 18 vocal req/min). Call lifecycle (/init → /start → /end) meters elapsed seconds strictly server-side; if TTS fails, the live transcript stays intact without inventing fallback audio.

VERIFICATION & GSM HARDWARE BRIDGE

Backed by a 303-assertion automated verification suite (177 TTS chunking/mode checks, 22 phonetic name-matching tests across 90 spellings, 40 emotion/sound tag checks, plus multi-key Gemini routing & retry tests) and an Android Kotlin Foreground Service (AudioPcmRelay.kt) relaying live PCM audio over WebSockets for GSM telephony.

ACCEPTED TRADE-OFF & KNOWN LIMIT

Routing Live text through Sawtify TTS adds latency over raw native Gemini audio, but delivers authentic Darija prosody and merchant voice consistency—with a single env flag (AGENT_LIVE_OUTPUT_MODE=gemini_live) to switch back when ultra-low latency outweighs dialectal fidelity.

ADR-005 · JAWEBFLOW · FIDALI · RAWDHA+ · MULTI-TENANT B2B ARCHITECTURE IN PRODUCTION

Rule-First Social Webhooks, Zero-Downtime Supabase Migration & App-Less QR/Push UX

Across B2B deployments (Instagram/Messenger automation in JawebFlow, retail loyalty in Fidali, nursery operations in RAWDHA+), the biggest failure modes are unnecessary LLM calls on deterministic events, silent client-SDK permission failures in serverless functions, and end-user app-install drop-off.

1. RULE-FIRST WEBHOOKS BEFORE LLM

On Instagram webhooks (comments, story replies, DMs), a deterministic matcher (case/accent-insensitive, supporting French, Arabic & Arabizi like “ch7al”) runs ahead of Gemini. High-volume triggers (“prix”, “livraison”, follow-gates) resolve without an LLM call—and keep working even when the merchant pauses AI.

2. SUPABASE POSTGRES + ZERO-APP UX

Migrated JawebFlow's core tables from Firestore REST to Supabase PostgreSQL (server-only service_role in Cloudflare Functions while keeping Firebase Auth tokens valid for zero-downtime migration). In Fidali & RAWDHA+, combined Supabase RLS with cryptographic browser QR codes + VAPID Web Push so customers can join without an app download.

ACCEPTED TRADE-OFF & KNOWN LIMIT

Maintaining dual local Express dev servers and Cloudflare Pages production functions requires shared TypeScript modules (functions/_shared/*) so business rules never diverge between dev and edge runtime—documented explicitly in AUDIT.md.
